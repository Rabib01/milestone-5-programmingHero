Best practise to appendChild ?? 

appendChild() is one of the most important DOM methods you'll use. The main best practice is to create the element first, configure it completely, and then append it only once.

Basic syntax
parent.appendChild(child);

Example:

const ul = document.querySelector("ul");

const li = document.createElement("li");
li.textContent = "Milk";

ul.appendChild(li);
✅ Best Practice 1: Configure before appending

Instead of this:

const li = document.createElement("li");

ul.appendChild(li);

li.textContent = "Milk";
li.className = "item";

Do this:

const li = document.createElement("li");

li.textContent = "Milk";
li.className = "item";

ul.appendChild(li);

This keeps your code easier to read and can reduce unnecessary browser updates.

✅ Best Practice 2: Store the parent element

Avoid repeatedly searching the DOM.

❌

document.querySelector("ul").appendChild(li1);
document.querySelector("ul").appendChild(li2);
document.querySelector("ul").appendChild(li3);

✅

const ul = document.querySelector("ul");

ul.appendChild(li1);
ul.appendChild(li2);
ul.appendChild(li3);
✅ Best Practice 3: Build complex elements before appending

Suppose you want:

<li>
    🍎 Apple
    <button>Delete</button>
</li>

Do this:

const li = document.createElement("li");
const button = document.createElement("button");

li.textContent = "🍎 Apple ";
button.textContent = "Delete";

li.appendChild(button);

ul.appendChild(li);

Notice that the <button> is added to the <li> before the <li> is added to the page.

✅ Best Practice 4: Use a DocumentFragment for many elements

If you're adding hundreds or thousands of elements, build them in memory first.

const fragment = document.createDocumentFragment();

for (let i = 1; i <= 1000; i++) {
    const li = document.createElement("li");
    li.textContent = `Item ${i}`;

    fragment.appendChild(li);
}

ul.appendChild(fragment);

This avoids repeatedly inserting into the live DOM.

✅ Best Practice 5: Prefer append() when appropriate

Modern JavaScript also has append().

ul.append(li);

Unlike appendChild(), append() can accept multiple nodes and strings:

ul.append(li1, li2, "Hello");

Whereas:

ul.appendChild("Hello");

❌ This throws an error because appendChild() only accepts a Node.

⚠️ Remember: appendChild() moves elements

If an element already exists in the DOM:

const div = document.querySelector(".box");

container1.appendChild(div);
container2.appendChild(div);

The <div> won't exist in both places. It gets moved from container1 to container2.

If you want a copy instead:

container2.appendChild(div.cloneNode(true));
Summary
Practice	Why?
Create → configure → append	Cleaner and more efficient
Cache parent elements	Avoid repeated DOM lookups
Build nested elements first	Easier to understand
Use DocumentFragment for many elements	Better performance with large lists
Use append() when you need strings or multiple nodes	More flexible API
Remember appendChild() moves existing nodes	Avoid unexpected behavior
Since you're learning React as well...

In vanilla JavaScript, appendChild() is a core skill because you're manually manipulating the DOM.

In React, you almost never call appendChild() yourself. Instead, you write JSX:

<ul>
  {items.map(item => (
    <li key={item.id}>{item.name}</li>
  ))}
</ul>

React figures out when to create, move, or remove DOM nodes and calls methods like appendChild() internally. That's why it's valuable to understand appendChild() now—it helps you appreciate what React is doing behind the scenes.

These positions tell the browser where to insert something relative to an existing element.
