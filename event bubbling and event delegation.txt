This is the w3c model 
If you mean the W3C Event Model, here's the short version:
The W3C Event Model says that when you click an element, the event travels in 3 phases:
Capturing phase 📥
The event goes from the document down to the target element.
Order: document → html → body → ... → button
Target phase 🎯
The event reaches the element that was actually clicked.
Bubbling phase 📤
The event travels back up from the target to the document.
Order: button → ... → body → html → document
Example:
<div>
  <button>Click me</button>
</div>
If you click the button:
Capturing: document → html → body → div → button
Target:    button
Bubbling:  button → div → body → html → document
By default, addEventListener() listens during the bubbling phase. If you pass { capture: true }, it listens during the capturing phase instead.

Best practise for event delegation according to GeePsT 

The best practice for event delegation is to attach one event listener to a common parent and let events bubble up from its children.

1. Attach the listener as low as possible

Don't attach it to document unless you need to.

❌ Avoid:

document.addEventListener("click", handleClick);

✅ Better:

const list = document.querySelector(".list");
list.addEventListener("click", handleClick);

This reduces unnecessary event handling.

2. Use event.target to find what was clicked
list.addEventListener("click", function (e) {
  console.log(e.target);
});
3. Use .closest() instead of checking event.target directly

If your button contains icons or spans, event.target might be one of those elements.

❌

if (e.target.classList.contains("delete-btn")) {

✅

const button = e.target.closest(".delete-btn");

if (!button) return;

console.log("Delete clicked");

closest() walks up the DOM until it finds the matching ancestor.

4. Return early

Avoid deeply nested if statements.

list.addEventListener("click", function (e) {
  const button = e.target.closest(".delete-btn");

  if (!button) return;

  // Handle deletion
});
5. Use data-* attributes for actions

Instead of many class checks:

<button data-action="edit">Edit</button>
<button data-action="delete">Delete</button>
list.addEventListener("click", function (e) {
  const button = e.target.closest("[data-action]");
  if (!button) return;

  switch (button.dataset.action) {
    case "edit":
      console.log("Edit");
      break;
    case "delete":
      console.log("Delete");
      break;
  }
});

This scales much better.

6. Only use delegation for bubbling events

It works well for events like:

✅ click
✅ input
✅ change
✅ keydown

It doesn't work directly for events that don't bubble, such as:

❌ focus
❌ blur

(You can use focusin and focusout instead.)

Example
<ul id="todos">
  <li>
    Buy milk
    <button class="delete-btn">Delete</button>
  </li>
</ul>
const todos = document.getElementById("todos");

todos.addEventListener("click", function (e) {
  const button = e.target.closest(".delete-btn");
  if (!button) return;

  button.closest("li").remove();
});
Only one event listener handles every current and future delete button.
Rule of thumb
Use one listener on the nearest common parent.
Use event.target.closest() to identify the intended element.
Use data-* attributes when handling multiple actions.
Return early if the click isn't relevant.
Delegate events only when the event bubbles.
